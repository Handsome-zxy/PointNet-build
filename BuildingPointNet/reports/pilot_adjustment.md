## 现象

第一轮 pilot（`tnet_on`, 2,000 step，反频率类别权重 `[1.731, 0.269]`）在 step 499 的验证结果：

| 指标 | 值 |
| --- | ---: |
| OA | 0.1778 |
| building precision | 1.0000 |
| building recall | 0.00418 |
| building F1 | 0.0083 |
| building IoU | 0.0042 |
| nonbuilding recall | 1.0000 |
| nonbuilding F1 | 0.2979 |
| mIoU | 0.0896 |
| building AP | 0.9976 |

## 诊断

- building AP=0.9976 说明概率排序几乎完美，模型已经学到了判别信号。
- 但 0.5 阈值下几乎全部预测为非建筑；反频率权重把建筑（训练集多数类，86.6%）
  的 CE 权重压到 0.269，使输出概率整体偏向非建筑。
- 这不是模型结构问题，而是损失权重/阈值不匹配。

## 调整

- 第一版改为**无类别权重 CE**（`class_weight_mode="none"`，权重 `[1.0, 1.0]`）+ Dice。
- Dice 仍然作用于 building 概率；数据划分、窗口、网络、增强、随机种子均未改动。
- 该调整是 pilot 后唯一超参数变更，正式实验会记录在 `config.json`。

## 后续检查

- 重新跑 600-step 校准 pilot，确认 0.5 阈值下 building F1/IoU 正常。
- 若仍存在概率校准问题，则在验证集上选择 building F1 最优阈值，并只用测试集做最终评估；
  阈值选择规则会写入实验记录。

  这些数字不能代表正式 8,000 step 的结果。
- 测试集 building recall 0.851、precision 0.692，非建筑 recall 0.408；模型偏保守/偏建筑，
  正式实验需要观察更长训练是否改善。
- 已加入验证集阈值扫描：每 1,000 step 计算 building F1 最优阈值；若优于 0.5 则测试使用该阈值，
  并同时报告 0.5 的指标。
- 正式实验改为 8,000 step、每 1,000 step 验证、patience=4；先跑 `tnet_on` seed 1234，观察
  1k/2k 的验证趋势，再决定是否启动其余 5 个 run。

## 1,000-step 正式 run 的第二个发现

第一次 8,000-step 正式 run 在 step 999 的验证结果：

| 阈值 | OA | building F1 | building IoU | non-building F1 | mIoU | building AP |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.50 | 0.2504 | 0.3645 | 0.2228 | 0.0863 | 0.1340 | 0.6774 |
| 0.06（mIoU/ F1 扫描） | — | 0.9054 | 0.8271 | — | — | — |

结论：模型输出概率存在明显负偏移，0.5 不是合适的工作点；若仍按 0.5 的 building IoU
选 checkpoint，会选到错误模型。

调整：

- 每个验证点扫描 0.01–0.99，选择**验证集 mIoU 最优**的阈值（同时兼顾建筑/非建筑）。
- checkpoint 也改为按该 mIoU 选择与早停。
- 测试同时报告 0.5 与调优阈值两套指标；测试 LAS 使用验证集选出的阈值。
- 该调整仅涉及评价/选择规则，不改变数据、网络、损失或对照条件。
- 第一次 8,000-step run 已停止并保留目录作为诊断记录；随后用新规则重新启动。
